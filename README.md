# Brushlink

名前は可視化分野の用語 **brushing and linking**（ある図でのドラッグ選択＝ブラッシングを、
他のすべての図にリンクさせて連動表示する手法）から。

**TIBCO Spotfire に着想を得た**、クロスフィルタ（マーキング）を Python / R で
再実装した探索的データ分析ダッシュボード。

散布図で範囲をドラッグすると、ヒストグラム・統計量・データ表が同時に絞り込まれ、
その選択範囲に対して R の統計モデルを走らせられる。

サイドバーのフィルタパネル（数値はレンジスライダー、カテゴリはチェックボックス）で
母集団そのものを絞り込むこともできる。フィルタとチャートの選択は別系統で、
「フィルタで母集団を絞り、その中でチャート選択する」という 2 段構えになっている。

## なぜクロスフィルタだけに絞ったか

Spotfire らしさはチャートの種類の多さではなく、次の 2 点にある。

1. **選択の連動** — ある図で選んだ対象が、他のすべての図で即座にハイライトされる
2. **速さ** — 大量データでもその連動が待ち時間なく返る

本プロジェクトはこの 2 点に機能を絞っている。

## 構成

| 層 | 実装 | 役割 |
|---|---|---|
| データ | DuckDB | インメモリ列指向エンジン。CSV / Parquet を SQL で扱う |
| 可視化 | HoloViews + hvPlot | `link_selections` によるチャート間の選択連動 |
| UI | Panel | ウィジェット・レイアウト・配信 |
| 統計 | R (rpy2) | 選択範囲に対するモデル当て。Spotfire の TERR に相当 |

```
app.py              アプリ本体（ウィジェットとレイアウトの組み立て）
src/data.py         DuckDB への読み込み・列メタ情報の推定
src/charts.py       チャート生成と選択連動
src/filters.py      フィルタパネルの生成と母集団の絞り込み
src/r_bridge.py     R 連携（R 不在時は numpy にフォールバック）
tests/smoke_test.py 連動と回帰が通ることの検証
```

### フィルタと選択の関係

- **フィルタ**（`src/filters.py`）は母集団そのものを絞る。結果の DataFrame が
  以降のチャート描画・統計量・データ表・R 回帰すべての入力元になる。
- **チャートの選択**（`link_selections`）は、フィルタ後の母集団の「中で」
  ドラッグして選ぶもので、フィルタとは別系統。
- **フィルタを変更すると、進行中のチャート選択はリセットされる。**
  母集団を作り直す設計上の割り切りで、フィルタと選択を厳密に同期させる
  複雑さを避けている。

### 設計上の判断

- **Streamlit ではなく Panel** — Streamlit はスクリプト全体を再実行するモデルのため、選択状態を保持し続けるクロスフィルタと相性が悪い。
- **Plotly/Dash ではなく HoloViews** — Dash ではチャート間の連動をコールバックで自前配線する必要がある。`link_selections` は同じ挙動を数行で与える。
- **pandas ではなく DuckDB** — 現状の規模なら pandas で足りるが、データ量が増えたときに集約を SQL 側へ寄せられる。

## 動かす

```bash
pip install -r requirements.txt
panel serve app.py --show
```

ブラウザが開いたら、散布図の上をドラッグして範囲を選択する。

自分のデータを使う場合:

```bash
panel serve app.py --show --args data/your.csv
```

数値列が 2 つ以上あれば、列の型は自動で判別される。

### R 連携を有効にする

R 本体を入れたうえで `pip install rpy2` すると、回帰が R の `lm()` 実行に切り替わり、
p 値まで表示される。R が無い環境では numpy による代替が動くため、アプリは止まらない。

### 動作確認

```bash
python tests/smoke_test.py
```
